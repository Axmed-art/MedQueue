# MedQueue

MedQueue — сайт для записи к стоматологу в Алматы. Пациент может найти клинику, выбрать свободное время и посмотреть свои записи в личном кабинете. Клиника подаёт заявку на сайте, а после одобрения получает доступ к расписанию.

Проект подготовила команда **MedLink**: А. Нұрболат, Д. Самира и Л. Артем.

Распределение ролей - Нұрболат - бэкэнд, логика; Самира - фронтенд, дизайн.

Сайт: https://medqueue-hs9r.onrender.com  
Репозиторий: https://github.com/Axmed-art/MedQueue

## Как запустить

В Windows откройте `start_medqueue.bat`. Когда в окне появится сообщение о запуске сервера, откройте <http://127.0.0.1:8000>.


## Что можно посмотреть

- На главной странице — короткое описание сервиса.
- В разделе «Клиники» — список клиник, поиск и доступное время.
- В «Кабинете» — регистрация пациента или клиники и вход в аккаунт.
- В кабинете клиники — управление расписанием после одобрения заявки.
- В панели владельца — заявки клиник и общая информация по сайту.
- В кабинете пациента — перенос записи, отмена не позднее чем за 2 часа, напоминание о визите и отзыв после приёма.
- На странице клиники — выбор даты в расписании и отзывы пациентов.


На локальном сервере создаётся демонстрационный вход владельца: `admin@medqueue.local` / `MedQueue123!`. Перед публикацией задайте `SITE_ADMIN_EMAIL` и `SITE_ADMIN_PASSWORD`.

## Развёртывание в Microsoft Azure

Проект можно разместить в Azure App Service на Linux с Python 3.12. В App Service задайте команду запуска `bash startup.sh` и следующие переменные окружения:

- `MEDQUEUE_DATA_DIR=/home/data` — постоянная папка для SQLite и фотографий.
- `SITE_ADMIN_EMAIL` и `SITE_ADMIN_PASSWORD` — учётные данные владельца сайта; задайте их до первого запуска.
- `PUBLIC_BASE_URL` — публичный HTTPS-адрес приложения.
- `RESEND_API_KEY` и `RESEND_FROM` — необязательно, для email-уведомлений.

Папка `/home` сохраняется между перезапусками Linux App Service. Для production с несколькими экземплярами перенесите данные в управляемую базу и объектное хранилище.

В репозитории есть GitHub Actions workflow `.github/workflows/azure-deploy.yml`. В GitHub добавьте repository variable `AZURE_WEBAPP_NAME` и secret `AZURE_WEBAPP_PUBLISH_PROFILE` (скачайте publish profile в Azure Portal у созданного Web App). Workflow запускается при push в `main` или вручную через **Actions → Deploy MedQueue to Azure App Service → Run workflow**.

## Email-уведомления

Для писем о новых и отменённых записях используется Resend. Без этих настроек сайт продолжает работать, но письма не отправляются.

В Resend нужно создать API-ключ и подтвердить домен отправителя. Затем добавьте в переменные окружения сервера:

- `RESEND_API_KEY` — API-ключ Resend.
- `RESEND_FROM` — подтверждённый адрес отправителя, например `MedQueue <notifications@ваш-домен.kz>`.

На Render эти значения задаются в **Dashboard → ваш сервис → Environment**. Не добавляйте API-ключ в код или репозиторий.

После успешной записи письмо получает пациент и клиника. При отмене записью уведомляется другая сторона.
